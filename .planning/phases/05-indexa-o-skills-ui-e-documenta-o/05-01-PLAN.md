<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> GitLab git over HTTPS | indexer clones/fetches with server-side credentials |
| server -> browser | sign-in error strings reach the UI via `/forge/status` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information disclosure | clone_url / indexer clone | mitigate | URL holds only host + full_name; credentials stay in `forge::apply_git_https_auth` (env/helper), never in the URL or logs |
| T-05-02 | Tampering | clone_url input | accept | `full_name` comes from the GitLab API stored in DB (path_with_namespace) and is passed as a git argv element, no shell |
| T-05-03 | Information disclosure | Code::Generic message | mitigate | static string, no token, host secret or raw glab output |
| T-05-04 | Spoofing | self-signed GitLab TLS during clone | mitigate | git inherits `GIT_SSL_CAINFO` set at boot by `gitlab/ca.rs`; TLS verification stays on |
</threat_model>
