<objective>
Put a provider seam (`backend/src/forge/`) between the rest of the backend and `backend/src/github/`, with zero GitHub behavior change (FORGE-02).

Purpose: Phase 2+ adds `Forge::GitLab` by extending one enum instead of touching ~30 call sites again.
Output: `backend/src/forge/mod.rs` (glob re-export of `crate::github` + `enum Forge { GitHub }` with three URL/refspec methods + one unit test), `mod forge;` in lib.rs, all `github::` call sites rewritten to `forge::`, and the hard-coded `https://github.com/...` and `refs/pull/<n>/head` literals moved into `Forge` methods that return identical bytes.

Design choices (Claude's discretion per CONTEXT; user priority is speed):
- Re-export via `pub(crate) use crate::github::*;` instead of wrapping functions or duplicating types (CONTEXT: "re-exportar via forge:: em vez de duplicar").
- `enum Forge { GitHub }` with `match` dispatch, no `dyn Trait` (CONTEXT locked decision).
- Selection: free fn `forge::current() -> Forge` returning `Forge::GitHub`, not a `ServerConfig` field. CONTEXT says selection comes from `ServerConfig` "por enquanto sempre GitHub"; the URL call sites are free functions with no config in reach, so threading config is not cheap. `current()` is the single place Phase 2 switches to read deploy config (`OCR_FORGE` is deferred to Phase 2). Marked with a `shortcut:` comment.
- Out of scope here: `full_name` two-segment rule (Phase 3 / FORGE-03), `FakeForge` (no test needs it), `OCR_FORGE`/host guard (Phase 2). No changelog fragment: AGENTS.md says internal changes get the `no-changelog` label instead.
</objective>
