<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /auth/gitlab/token | untrusted JSON body carrying a secret |
| server -> glab child | secret crosses a process boundary |
| glab output -> HTTP response / logs | child output may echo the secret |
| server -> GitLab host | token must reach only the configured host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-15 | Information disclosure | token in argv/env/proc list | mitigate | stdin only; fake-glab test asserts token absent from args.log and env.log |
| T-02-16 | Information disclosure | serde error echo | mitigate | parse_token_body maps any serde error to fixed "Invalid request body."; no Debug on TokenBody; route test with a JSON-string body |
| T-02-17 | Information disclosure | glab output in errors/logs | mitigate | redact() on every child output before use; classified fixed copy returned to the browser |
| T-02-18 | Information disclosure | token sent to wrong host | mitigate | `--hostname H` + `GITLAB_HOST=H` from the validated forge host; inherited GITLAB_TOKEN/GITLAB_ACCESS_TOKEN/OAUTH_TOKEN/GLAB_TOKEN removed |
| T-02-19 | Tampering | CSRF connecting an attacker token | mitigate | require_trusted_origin on both POSTs + global JSON content-type check + OCR_API_TOKEN auth (routes not public) |
| T-02-20 | Information disclosure | token at rest | accept | stored only by glab in $OCR_DATA_DIR/glab (0700, `--insecure-storage`), same threat model as gh hosts.yml; never in DB |
| T-02-21 | Denial of service | hung glab | mitigate | 20s deadline with kill in run_glab |
| T-02-22 | Elevation of privilege | runners | mitigate | glab only spawned by the server; config dir in server-only data volume (static check from plan 02-02) |
</threat_model>
